# Technical Specification: Streaming RAG API Integration (`/api/chat/stream`)

## 1. Protocol Architecture & Transport Layer

The Document Copilot streaming service implements **Server-Sent Events (SSE)** over standard HTTP/1.1 and HTTP/2 connections using chunked transfer encoding.

- **Endpoint**: `POST /api/chat/stream`
- **Request Payload**: `application/json`
- **Response Content-Type**: `text/event-stream`
- **Response Headers**:
  - `Content-Type: text/event-stream; charset=utf-8`
  - `Cache-Control: no-cache, no-transform`
  - `Connection: keep-alive`
  - `X-Accel-Buffering: no` *(Disables reverse-proxy buffering in Nginx/Vercel/Cloudflare)*

```
[ Frontend Client ]                                      [ FastAPI Backend ]
        │                                                         │
        │─── POST /api/chat/stream ──────────────────────────────►│
        │    Headers: Content-Type: application/json              │
        │    Body: {"question": "...", "session_id": "..."}       │
        │                                                         │
        │    [HTTP 200 OK + Transfer-Encoding: chunked]           │
        │◄── Response Stream Opened ──────────────────────────────│
        │                                                         │
        │    [Phase 1: Hybrid Retrieval + Cross-Encoder Rerank]   │
        │    (Backend retrieves ChromaDB + BM25, no tokens yet)   │
        │                                                         │
        │    [Phase 2: LLM Token Generation]                      │
        │◄── data: {"token": "Tesla"}\n\n ────────────────────────│
        │◄── data: {"token": "'s"}\n\n ───────────────────────────│
        │◄── data: {"token": " Q4"}\n\n ──────────────────────────│
        │    ...                                                  │
        │                                                         │
        │    [Phase 3: Stream Teardown]                           │
        │◄── data: [DONE]\n\n ────────────────────────────────────│
        │    (Stream closes cleanly)                              │
```

## 2. Wire Protocol & Event Framing

Each data chunk adheres strictly to the W3C SSE standard:
`data: <JSON_OR_SENTINEL>\n\n`

### 2.1 Standard Token Frame
```text
data: {"token": "string"}\n\n
```
- `token`: Partial string segment generated by the LLM (may be whitespace, word piece, punctuation, or table markdown snippet).

### 2.2 Terminal Sentinel Frame
```text
data: [DONE]\n\n
```
- Sent as the final frame. Signals the client to terminate the read loop and finalize state.

### 2.3 Error Frame
```text
data: {"error": "Error description"}\n\n
data: [DONE]\n\n
```
- Emitted when an exception occurs during context retrieval or LLM inference.

## 3. Analysis of Common Frontend Pitfalls

### Pitfall A: Full Page Reload on Submission
- **Root Cause**: When a user presses `Enter` inside an `<input>` nested in a `<form>`, the browser executes the default HTTP form submission, reloading the entire DOM.
- **Remedy**: Always intercept the form submit event: `event.preventDefault()`.

### Pitfall B: Delayed / Non-Streaming Render (Buffering)
- **Root Cause**: Calling `await response.text()` or `await response.json()` instructs the browser's HTTP client to accumulate the complete byte stream in memory before resolving the Promise.
- **Remedy**: Utilize `response.body.getReader()` (`ReadableStreamDefaultReader`) with incremental decoding.

### Pitfall C: TCP Packet Fragmentation & Incomplete JSON Chunks
- **Root Cause**: A single SSE event may be split across multiple TCP packets, or multiple SSE events may arrive in a single `Uint8Array` chunk. Naively calling `JSON.parse(chunk)` will cause syntax errors.
- **Remedy**: Maintain an internal string buffer. Split on `\n\n` delimiters and retain any trailing incomplete fragment for the next read cycle.

### Pitfall D: Stale React State Closures
- **Root Cause**: In asynchronous stream consumption loops, referencing `answer` directly (e.g. `setAnswer(answer + token)`) captures stale closure values.
- **Remedy**: Always use functional state dispatch: `setAnswer((prev) => prev + token)`.

## 4. Production-Ready TypeScript Hook Implementation

This hook encapsulates request cancellation (`AbortController`), chunk reassembly, error handling, and state progression.

```typescript
import { useState, useRef, useCallback } from 'react';

export interface StreamState {
  answer: string;
  isSearching: boolean;
  isStreaming: boolean;
  error: string | null;
}

export function useDocumentCopilotStream(apiBaseUrl: string = 'http://localhost:8000') {
  const [state, setState] = useState<StreamState>({
    answer: '',
    isSearching: false,
    isStreaming: false,
    error: null,
  });

  const abortControllerRef = useRef<AbortController | null>(null);

  const stopGeneration = useCallback(() => {
    if (abortControllerRef.current) {
      abortControllerRef.current.abort();
      abortControllerRef.current = null;
    }
    setState((prev) => ({
      ...prev,
      isSearching: false,
      isStreaming: false,
    }));
  }, []);

  const sendQuery = useCallback(
    async (question: string, sessionId?: string) => {
      if (!question.trim()) return;

      // Abort any active request before starting a new one
      stopGeneration();

      const controller = new AbortController();
      abortControllerRef.current = controller;

      setState({
        answer: '',
        isSearching: true, // Backend is performing Hybrid Search + Reranking
        isStreaming: false,
        error: null,
      });

      try {
        const response = await fetch(`${apiBaseUrl}/api/chat/stream`, {
          method: 'POST',
          headers: {
            'Content-Type': 'application/json',
            'Accept': 'text/event-stream',
          },
          body: JSON.stringify({
            question: question.trim(),
            session_id: sessionId ?? null,
          }),
          signal: controller.signal,
        });

        if (!response.ok) {
          const errorText = await response.text();
          throw new Error(`HTTP ${response.status}: ${errorText || response.statusText}`);
        }

        if (!response.body) {
          throw new Error('ReadableStream unavailable on response.');
        }

        const reader = response.body.getReader();
        const decoder = new TextDecoder('utf-8');
        let streamBuffer = '';

        while (true) {
          const { done, value } = await reader.read();
          if (done) break;

          // Decode incoming byte chunk
          streamBuffer += decoder.decode(value, { stream: true });

          // Split by SSE delimiter: double newline
          const eventBlocks = streamBuffer.split('\n\n');
          // Preserve trailing incomplete block
          streamBuffer = eventBlocks.pop() || '';

          for (const block of eventBlocks) {
            const line = block.trim();
            if (!line.startsWith('data: ')) continue;

            const payload = line.slice(6).trim();

            if (payload === '[DONE]') {
              setState((prev) => ({
                ...prev,
                isSearching: false,
                isStreaming: false,
              }));
              return;
            }

            try {
              const data = JSON.parse(payload);

              if (data.token) {
                setState((prev) => ({
                  ...prev,
                  isSearching: false, // Transition from search to streaming on first token
                  isStreaming: true,
                  answer: prev.answer + data.token,
                }));
              }

              if (data.error) {
                setState((prev) => ({
                  ...prev,
                  isSearching: false,
                  isStreaming: false,
                  error: data.error,
                }));
              }
            } catch (jsonErr) {
              console.warn('[SSE] JSON parse skip on block:', payload);
            }
          }
        }
      } catch (err: any) {
        if (err.name === 'AbortError') {
          console.log('[SSE] Stream aborted by user.');
          return;
        }
        setState((prev) => ({
          ...prev,
          isSearching: false,
          isStreaming: false,
          error: err.message || 'An unexpected streaming error occurred.',
        }));
      } finally {
        abortControllerRef.current = null;
      }
    },
    [apiBaseUrl, stopGeneration]
  );

  return {
    answer: state.answer,
    isSearching: state.isSearching,
    isStreaming: state.isStreaming,
    error: state.error,
    sendQuery,
    stopGeneration,
  };
}
```

## 5. UI Rendering Guidelines (Markdown & Tables)

Because the backend outputs raw Markdown tables and formatted paragraphs, the UI should render markdown incrementally:

1. **Parser**: Use `react-markdown` with `remark-gfm` (GitHub Flavored Markdown for table parsing).
2. **Smooth Cursor**: Render a blinking inline cursor `<span>` only while `isStreaming === true`.
3. **Status Indicators**:
   - `isSearching === true`: Display `"Analyzing document & retrieving sections..."` with an indeterminate progress spinner.
   - `isStreaming === true`: Hide the search spinner and render tokens as they stream in.
